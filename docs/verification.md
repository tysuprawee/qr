The browser tests use separate desktop and phone cookie contexts and a simulated rear-camera stream. They exercise the QR invitation target, fallback code, desktop approval, camera interaction, photo upload, WebSocket delivery, polygon masking, real unavailable-worker error, explicitly labeled demo import, dimension confirmation, object placement, persistence, disconnection and photo deletion. The success-path test uses a separate synthetic HTTP worker fixture to verify transport through GLB preview, library insertion and movement. It does not establish AI reconstruction quality.

Layout tests cover normalized metadata import, planar alignment and project export/import. Backend tests cover permission boundaries, origin checks, rate limiting, invitation expiry, file-size/type checks, decoded image output, metadata removal, phone revocation, successful GLB delivery, and timed photo/session cleanup.
